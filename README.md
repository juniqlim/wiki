# 나의 위키

md 파일을 정적 위키 사이트로 만든다. 런타임 의존성 없음.

읽는 곳 — https://wiki.juniq.im

## 빌드

    node build.js        # → docs/

Node 18+ 만 필요하다. npm 패키지 없음.

## 구조

    site.json            사이트 제목 · 옆 사이트 · 옮긴 노트 주소
    wiki/*.md            위키 문서 — 파일명이 곧 문서 이름
    build.js             md 읽기 → 파싱 → docs/ 출력
    site/md.js           마크다운 파서 (프론트매터 · 표 · 중첩 리스트 · 링크 수집)
    site/render.js       AST → HTML, 페이지 레이아웃
    site/style.css       스타일 (다크 기본 / 라이트 토글)
    site/app.js          테마 토글 + 클라이언트 검색
    test/                단위 테스트 — npm test
    docs/                배포물. Pages 로 올리므로 커밋한다

## 쓰는 규칙

- `wiki/` 에 md 를 넣는다. 파일명이 문서 이름이고 그대로 URL 이 된다.
- `[[이름]]` 으로 다른 문서를 부른다. `[[이름|글자]]` 로 보이는 글자를 바꾼다.
- 없는 문서를 불러도 된다. 첫 화면의 "아직 쓰지 않은 문서" 에 모인다.
- 영어 이름은 CamelCase 로 쓰면 대괄호 없이 링크된다. 단 문서가 실제 있을 때만.
- 부른 쪽 · 불린 쪽 모두 문서 아래에 연결이 자동으로 생긴다.
- 이름을 바꿀 때는 프론트매터에 `aliases: 옛이름` 을 적는다. 옛 주소가 새 주소로 간다.
- 날짜는 적지 않는다. 언제 고쳤는지는 git 이 알고, `/RecentChanges` 에 최근 고친 순서로 나온다.
- 영어 이름에 한글 제목을 붙이려면 `title: 한글 제목` 을 적는다. 문서 머리와 목록, 검색에 함께 나온다.

## 노트와 위키

둘은 역할이 다르고 사이트를 따로 둔다. 노트는 https://note.juniq.im 이다.

|  | 노트 | 위키 |
|---|---|---|
| 담는 것 | 글 한 편 | 개념 하나 |
| 이름 | 제목 문장 | 본문에서 부를 이름 |
| 날짜 | 쓴 날이 붙는다 | 없다. 계속 고친다 |
| 링크색 | 초록 | 파랑 |

노트는 2026-08-11 에 이 저장소에서 나갔다. 그때까지 `wiki.juniq.im/notes/...` 로
나간 링크가 있으므로, `site.json` 의 `moved` 에 옛 주소를 적어 두고 노트 사이트의
같은 경로로 보낸다. 옛 주소를 지우면 밖에서 걸어 둔 링크가 죽는다.

## 배포 (GitHub Pages)

`docs/` 를 커밋해서 올린다. 문서를 고친 뒤:

    node build.js
    git add -A && git commit && git push

저장소 Settings → Pages 에서 소스는 `main` 브랜치 `/docs`.

## 남은 일

- 노트가 나가며 안 쓰게 된 코드 걷어내기 (`md.js` 의 날짜 · 폴더 · slug, `.md` 상대경로 링크, `style.css` 의 노트 전용 클래스)
- 고침 날짜 · 편집 횟수를 git 커밋 이력에서 채우기
